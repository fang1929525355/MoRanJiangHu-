# 酒馆预设字数例外与文章优化超时设计

## 目标

1. 酒馆预设继续接管文风、格式、COT 与免责声明，但必须遵守玩家设置的正文最低字数。
2. 文章优化在兼容接口已停止产出、却未发送结束标记或关闭连接时，不再无限阻塞后台队列。

## 酒馆预设字数例外

- 使用酒馆预设时，将运行时生成的最低字数要求作为独立的最终 `user` 消息注入。
- 字数消息位于预设消息链之后，确保它是本回合的最终硬约束之一。
- 不恢复项目风格助手、输出格式、免责声明或其他被酒馆预设接管的提示词。
- 普通模式现有消息顺序保持不变。
- 开局或主剧情只要复用酒馆预设主消息链，就遵循相同规则。

## 文章优化超时

- 文章优化读取现有 `游玩请求超时设置`：等待首个增量使用“首次响应超时”，收到增量后使用“流式空闲超时”。
- 每次收到流式增量时重置空闲计时器。
- 空闲超时时，若累计输出已经包含完整闭合的 `<正文>...</正文>`，接受当前草稿并主动中止仍挂起的底层请求。
- 空闲超时时，若正文标签不完整，则抛出明确超时错误，进入现有自动重试与“重试/跳过”决策链路。
- 非流式请求使用首次响应超时作为整次请求上限，防止永久等待。
- 普通回合和开局文章优化共用同一套超时封装，避免行为分叉。
- 父级取消信号始终优先，用户主动中止不得被转换为可接受草稿。

## 错误与可观测性

- 超时错误需区分“等待首次响应超时”和“流式输出空闲超时”。
- 接受完整草稿时记录诊断信息，但不向玩家暴露提示词、隐藏天赋或 API 密钥。
- 不完整输出超时后，界面必须离开持续运行状态并进入现有失败处理流程。

## 测试

- 酒馆预设会收到玩家设置的最低字数消息。
- 酒馆预设仍不会收到项目输出协议和风格助手。
- 正常模式字数消息行为不变。
- 文章优化无首个增量时按配置超时。
- 文章优化产生部分正文后停止时按空闲时间超时。
- 已收到完整闭合正文但连接挂起时接受草稿。
- 父级取消仍抛出 `AbortError`。
- 普通回合与开局文章优化均通过对应工作流测试。

## 非目标

- 不改变字数容错比例和文章优化二次扩写策略。
- 不改写或迁移玩家已有酒馆预设。
- 不在本次修改其他独立阶段的超时实现。
