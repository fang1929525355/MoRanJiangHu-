# 模式包叙事方向覆盖设计

## 目标

让玩家能够从官方基础模式创建真正可改造的模式包，并分别控制主线方向、剧情暗线和世界推进风格；同时保持现有模式包、旧存档和未知扩展字段完全兼容。

## 已确认问题

当前创意工坊虽然提供“下载官方模板”和“载入表单”，但只复制官方运行时配置。题材口径、世界规则和能力体系使用占位文字，主线方向、暗线策略和世界推进规则也没有独立编辑入口。

这会导致玩家虽然修改了模式包表层内容，正文、剧情规划或后台世界演变仍可能继续采用官方基础模式和通用提示词的默认倾向。

## 方案

采用受控覆盖，而不是开放底层完整系统提示词。

模式包贡献草稿新增三个可选文本字段：

- `mainStoryDirection`：主线方向，约束主线目标、冲突强度、节奏和长期基调。
- `hiddenPlotPolicy`：暗线策略，约束伏笔、阴谋、信息差和隐藏威胁的强度与边界。
- `worldEvolutionPolicy`：世界推进规则，约束后台势力、社会事件和非玩家区域的演变方式。

三个字段为空时不注入任何新规则，保持原有模式包行为。字段有内容时，将生成独立的模式世界书条目，并只进入与其职责相关的作用域：

- 主线方向：`main`、`opening`、`story_plan`、`heroine_plan`。
- 暗线策略：`main`、`opening`、`story_plan`、`heroine_plan`、`world_evolution`。
- 世界推进规则：`world_evolution`、`story_plan`，并在 `main` 中提供必要的结果承接约束。

这些覆盖只改变叙事取向，不允许覆盖变量协议、命令格式、数据结构、安全规则、存档一致性规则或系统级输出约束。

## 官方模板

官方模板应加载所选官方模式真实可用的题材口径、世界规则和能力体系摘要，不再使用“在此填写”的占位正文。

官方模板中的三个新增字段提供与该题材一致的默认叙事方向。玩家可以直接在表单中修改，也可以下载 JSON 后外部编辑再导入。

## 数据兼容

- 新字段全部可选，旧模式包缺失字段时按空字符串处理。
- 旧模式包导入、保存、重新载入后，原有 `modeRuntimeProfile`、`modeWorldbooks`、`contentBlocks`、预设、地图 DIY 和未知扩展字段继续保留。
- 不修改游戏存档结构，不要求旧存档迁移。
- 分段模式包和普通题材模块继续沿用现有协议；新增字段只属于完整模式包。
- 模块往返转换必须保留新增字段，也不得因为字段缺失而生成无意义的空世界书条目。

## 界面

在完整模式包贡献表单中新增“叙事方向控制”区域，包含三个文本框和简短说明。普通题材模块不显示该区域。

字段文案应明确：这些设置控制叙事倾向，不会覆盖底层数据和安全规则。界面需要在桌面、移动宽度和白天主题下保持可读。

## 测试与验收

自动化测试覆盖：

- 旧模式包缺失新增字段时，构建结果和原有注入行为保持不变。
- 新模式包往返转换完整保留三个字段。
- 只有非空字段才生成对应世界书条目。
- 三类条目的作用域符合职责边界。
- 官方现代都市模板包含真实内容和可编辑叙事方向，不再包含占位正文。
- “轻松愉快现代都市”规则能够进入正文、开局、剧情规划和世界演变的最终提示词上下文。
- 未知扩展字段在编辑往返后仍保留。

端到端测试覆盖：

1. 打开创意工坊并载入现代都市官方模板。
2. 确认真实官方内容和三个叙事字段已显示。
3. 修改为轻松日常方向，保存为本地模式包。
4. 重新载入并确认内容无损。
5. 新开局选择该模式包，验证最终注入预览或实际请求上下文包含三类规则。
6. 检查桌面、移动宽度和白天主题可读性。

## 发布

自动化测试、生产构建和端到端验证通过后，按项目发布规则升级版本，刷新最终发布时间，构建并校验 APK，上传公开下载渠道，部署主备域名，分别验证静态资源、更新清单、APK 和线上行为，提交并推送发布备份，最后检查目标仓库对应提交的 GitHub Actions CI。
