# 超凡题材视觉年龄统一解析设计

## 目标

解决角色真实年龄被机械映射为现实老年外貌的问题，并让剧情称呼、外貌档案、角色锚点、玩家生图和 NPC 生图使用同一套视觉年龄判断。

本设计区分两个概念：

- 真实年龄：用于出生时间、经历长度、辈分、寿元消耗和历史关系。
- 视觉年龄：用于面容、体态、剧情外貌措辞、称呼约束和生图标签。

例如，85 岁金丹修士仍然保留 85 岁的经历和资历，但在没有老态、寿元枯竭或异常衰老证据时，不应默认生成老妇外貌。

## 非目标

- 不修改角色真实年龄。
- 不把所有高境界角色统一年轻化。
- 不批量改写旧存档或删除已生成图片。
- 不在本次改动中建立完整的跨题材寿元模拟系统。
- 不仅通过添加一段提示词掩盖现有冲突，而是消除各调用链对年龄的不同解释。

## 根因

现有 NPC 生图流程已经提示模型：修炼、长生或驻颜角色的视觉年龄应跟随身份、境界、外貌和正文事实。但是后续硬编码仍会为所有成年人加入类似以下标签：

```text
85 years old, adult, age-accurate face
```

真实岁数和 `age-accurate face` 对图像模型形成更直接的现实衰老约束，覆盖了前面的长生语境说明。

此外，现有长生判断主要扫描单个 NPC 文本中的“金丹、元婴、驻颜”等关键词，没有稳定读取全局题材、运行时模式、种族寿命和能力体系，因此无法覆盖无限流、西方奇幻、灵气复苏和自定义超凡世界，也无法可靠区分现实人物与超凡人物。

## 方案选择

采用“统一视觉年龄解析器 + 可选明确覆盖字段”的兼容方案。

没有选择仅修改 NPC 生图提示词，因为剧情称呼、外貌档案、玩家生图和角色锚点仍会继续产生冲突。没有选择为所有角色强制新增必填视觉年龄字段，因为旧存档缺少该字段，而且大量角色应当可以依据题材和档案自动推导。

统一解析器是视觉年龄的唯一派生入口。角色可以通过明确的 `外观年龄` 或外貌事实覆盖自动推导；未明确时，解析器根据题材、真实年龄、境界、种族、身份、外貌和特殊状态动态计算，不强制写回旧存档。

## 数据模型

### 可选角色字段

玩家与 NPC 档案允许增加可选字段：

```ts
外观年龄?: number | string;
```

允许数字或自然语言，是为了兼容“看起来三十岁上下”“青年外貌”“垂暮老者”等已有表达。数字表示明确的视觉年龄，不改变真实年龄。

第一版不要求所有生成器都输出该字段，也不迁移旧数据。字段缺失时只做运行时推导。

### 解析输入

```ts
interface VisualAgeContext {
    actualAge?: number;
    explicitVisualAge?: number | string;
    topic?: string;
    runtimeMode?: string;
    realmName?: string;
    realmLevel?: number;
    species?: string;
    identity?: string;
    appearance?: string;
    profileText?: string;
    statusText?: string;
}
```

调用方只传递已有信息，不负责自行解释“金丹是否年轻”或“无限流是否延寿”。题材相关信息应优先来自全局题材与运行时配置，角色文本只作为补充证据。

### 解析输出

```ts
type VisualAgeBand =
    | 'child'
    | 'early_teen'
    | 'late_teen'
    | 'young_adult'
    | 'mature_adult'
    | 'middle_aged'
    | 'elderly'
    | 'unknown';

interface VisualAgeResolution {
    actualAge?: number;
    visualAgeBand: VisualAgeBand;
    suggestedVisualAge?: number;
    source: 'explicit' | 'appearance' | 'status' | 'species' | 'supernatural' | 'realistic' | 'unknown';
    reasons: string[];
    positiveTags: string[];
    negativeTags: string[];
    narrativeConstraints: string[];
    explicitYouthfulAppearance: boolean;
}
```

`suggestedVisualAge` 只在证据足够时输出。信息不足时输出年龄段而不是伪造精确岁数。`reasons` 用于测试和诊断，不直接暴露给玩家。

## 解析规则

### 优先级

按以下顺序解析，高优先级事实可以阻止低优先级规则覆盖：

1. 明确 `外观年龄` 或无歧义的外貌描述。
2. 驻颜、返老还童、寿元将尽、诅咒衰老、时间侵蚀等特殊状态。
3. 种族的生命周期与成熟速度。
4. 题材是否允许超凡延寿或肉身强化。
5. 境界、能力或强化等级在当前体系中的相对档位。
6. 信息不足时保守回退。

“长老”“前辈”“老祖”等身份只表示地位或资历，不单独证明老年脸。“老妪”“白发苍苍、皱纹深重”“寿元枯竭”等明确外貌或状态才构成老态证据。

### 题材分档

- 强长生题材：仙侠、修真、都市修仙、灵气复苏等。达到体系中明确具有延寿或肉身蜕变意义的阶段后，真实年龄不再直接映射视觉年龄。
- 条件超凡题材：无限流、武侠、西方奇幻、末日强化、自定义超凡模式等。只有角色确实拥有强化、血统、能力、道具或长寿种族证据时才启用超凡推导；普通人继续现实衰老。
- 现实衰老题材：完全现实的现代、历史或无超凡能力人物。默认按真实年龄推导外貌。

无限流不是全员驻颜。轮回者、强化者或拥有超凡血统者按能力证据判断，未强化的现实人物仍按现实年龄判断。

### 境界与能力

境界判断使用相对档位，不把“金丹”之类名称写死为所有世界通用规则：

- 优先读取已有 `境界层级`、DIY 境界母板或能力体系映射。
- 在强长生题材中，中高档位且无衰老证据的成年人默认保持青年到成熟成年外观。
- 低境界或尚未获得延寿能力的角色不能仅凭“修士”身份跳过现实衰老。
- 高境界也不能覆盖明确老态、寿元将尽、功法副作用或角色主动维持老年形象的设定。
- 自定义体系没有延寿含义时，不依据战力自动年轻化。

第一版使用可测试的规则表和题材引导，不尝试计算精确寿元。后续若能力体系提供结构化寿元信息，可作为解析器的新输入，不改变调用方接口。

### 未成年安全边界

- 真实年龄未满 18 岁时，不得因为高境界、长寿种族或能力而成人化。
- 真实年龄已成年但明确为幼态外观时，视觉输出必须保留幼态约束，并禁止成人私密生图路径。
- 真实年龄不明且视觉年龄也不明时，不得默认生成未成年外观。
- 成人私密生图资格不能只看真实年龄；必须同时确认真实年龄成年，且没有明确未成年或幼态视觉证据。

## 统一调用链

### 角色上下文

`npcContext` 在组织 NPC 和玩家快照时保留真实年龄、可选外观年龄、境界层级、种族、身份、外貌与状态。它不生成英文年龄标签，也不自行判断是否驻颜。

### NPC 生图

NPC 生图流程在生成提示词前调用统一解析器：

1. 使用视觉年龄结果生成性别与年龄正向标签。
2. 超凡成年人不再拼入真实岁数和 `age-accurate face`。
3. 只有现实衰老分支或明确外观年龄时，才加入与视觉年龄一致的精确年龄标签。
4. 根据解析结果添加或排除 `elderly`、`wrinkles`、`frail body`、`child` 等标签。
5. 词组转化、最终强制词组和负向提示词全部使用同一个解析结果，避免后续重新按真实年龄覆盖。

现有男娘、扶她及其他性别表现逻辑继续保留，但其年龄标签改为接收视觉年龄结果。性别表达不能绕过未成年安全规则。

### 玩家生图

玩家生图使用与 NPC 相同的解析器和提示词构建函数。玩家档案中明确的外观年龄、外貌描述与特殊状态优先于自动推导，避免主角和 NPC 在同一世界使用不同年龄规则。

### 角色锚点与外貌档案

- 自动提取的锚点记录与视觉年龄相关的来源摘要或版本标识。
- 重新生图时，如果自动锚点含有与当前解析结果冲突的老年、幼年或精确年龄标签，则判定为过期并重新提取或过滤冲突标签。
- 玩家手动编辑的锚点不自动覆盖。若手动锚点与安全规则冲突，生图阶段仍追加安全硬约束；其他冲突保留用户选择。
- 旧图片不自动删除。用户主动重新生成时才应用新规则。

### 剧情与称呼

向剧情模型提供简洁的视觉年龄约束：真实年龄代表经历，视觉年龄代表外观。只有视觉年龄为老年或正文明确老态时，才允许使用“老妇、老妪、老太婆”等外貌称呼。

“前辈、长老、老祖”仍可依据身份和辈分使用，不要求角色具有老年面容。剧情约束不把推导出的精确视觉年龄强制写入正文，除非角色档案已有明确设定。

## 示例

清霜的输入：

```text
真实年龄：85
题材：仙侠
境界：金丹四层
身份：玉仙宗巡查使
体态：挺拔、敏捷
老态证据：无
```

预期解析：

```text
视觉年龄段：成熟青年 / mature_adult
建议视觉年龄：约 36 岁
依据：强长生题材 + 中高境界 + 健康体态 + 无老态描述
正向标签：adult woman, mature youthful face, physically vigorous
负向标签：elderly woman, old face, wrinkles, frail body
剧情约束：可以称前辈或巡查使，不因 85 岁称老妇或老太婆
```

建议年龄只是提示词锚点，允许在 32 至 40 岁的成熟成年观感内波动，不写回真实年龄。

反例：同为 85 岁的金丹修士，如果档案明确“寿元将尽、面容枯槁、皱纹纵横”，应解析为老年外观。条件超凡题材中的 85 岁普通现实人物，没有任何强化或长寿证据时也应按现实老年处理。

## 兼容与错误处理

- 缺少题材信息时，优先读取运行时配置和已有世界说明；仍无法判断时，不添加精确真实岁数标签，并保留成人、未成年等最低限度安全约束。
- 境界名称无法映射时，不凭关键词强行认定高境界；结合角色明确状态和外貌保守判断。
- `外观年龄` 格式无法解析时忽略该字段并记录诊断原因，不阻断剧情或生图。
- 多条高优先级事实冲突时，安全规则优先；非安全冲突优先采用更具体、更新的角色档案事实，并在结果中保留原因。
- 解析器异常时，成人角色回退为不含精确岁数的 `adult`，未成年人回退为真实年龄对应的安全年龄段，避免恢复到“所有成年人按真实岁数画脸”的旧行为。

## 测试策略

### 解析器单元测试

- 85 岁金丹修士、无老态描述，解析为成熟成年而非老年。
- 85 岁金丹修士、寿元将尽且明确枯槁，解析为老年。
- 85 岁现实普通人，解析为老年。
- 无限流中的高龄强化者按强化证据推导；同世界普通人按现实年龄推导。
- 长寿种族按种族生命周期推导。
- “长老、老祖”不单独触发老年外观。
- 明确外观年龄覆盖自动推导，但不修改真实年龄。
- 未成年人不会被高境界成人化。
- 成年幼态角色触发私密生图禁止条件。
- 信息不足时不生成伪精确年龄。

### 生图工作流测试

- 超凡高龄成年人最终提示词不包含真实岁数和 `age-accurate face`。
- 现实高龄成年人仍包含与视觉年龄一致的老年标签。
- 正向、负向、词组转化和最终强制词组使用同一视觉年龄结果。
- 玩家与 NPC 对相同上下文生成一致的年龄标签。
- 明确老态不会被“高境界年轻化”覆盖。
- 自动旧锚点中的冲突老年标签会被判定过期或过滤。
- 手动锚点不会被自动重写，但安全约束仍然生效。

### 剧情与回归测试

- 高龄高境界角色不会仅因真实年龄被描述为老妇或老妪。
- 身份称呼“长老、前辈、老祖”继续可用。
- 旧存档缺少 `外观年龄` 时可以正常加载和生图。
- 已生成图片不被自动删除。
- 现有性别表达、私密生图资格、题材图像引导和角色锚点测试继续通过。
- 相关 Vitest、TypeScript 检查和生产构建通过。

## 完成标准

- 清霜这类超凡高龄角色在无老态证据时不再生成老太太外貌。
- 完全现实人物仍遵循现实年龄与衰老规律。
- 无限流等条件超凡题材按角色实际强化证据区分，不全员年轻化。
- 高境界不能覆盖明确老态、寿元枯竭、诅咒或主动老年形象。
- 玩家、NPC、剧情称呼、外貌档案、锚点和生图使用同一视觉年龄结论。
- 真实年龄、历史经历和辈分语义保持不变。
- 旧存档无需迁移，旧图片无需自动重生成。
- 本阶段只完成本地实现与验证，不部署。
