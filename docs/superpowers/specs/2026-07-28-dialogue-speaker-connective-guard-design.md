# 正文说话人连接词误判修复设计

## 问题

严格正文校验会检查旁白中是否混入未使用 `【角色名】` 标签的直接对白。当前说话人提取允许任意两到三个汉字作为未知人物名，因此在“苏辰没有急着饮茶，而是看着烛火，随后开口：‘……’”这类句子中，会把离“开口”较近的“而是”截成说话人候选。

解析失败恢复弹窗的“自动修复并应用”和“手动编辑后应用”都会重新调用同一正文解析器。两条路径都返回相同错误，是校验器稳定误判，不是弹窗缓存旧错误。

## 方案选择

采用统一的叙事连接词排除修复：把“而是、但是、可是、不过、于是、因此、所以、因为”等明确连接词以整词匹配方式纳入公共说话人守卫，并让无标签动作行提取器复用同一个叙事短语分类函数。引号对白检测与相邻动作/口语检测两条说话人提取路径都会得到一致保护，且不维护两份容易漂移的连接词列表。

连接词不能作为正式人物标签的无条件前缀排除条件，否则会误伤“于是之”这类以连接词开头的真实姓名。正式标签只有完整等于连接词时才拒绝；候选为“于是之”等真实姓名时仍走正常人物名判断。

自动提取说话人时，凡候选以连接词开头，默认按叙事短语拒绝；只有角色名单或场景已知人物明确声明该名称，或者候选本身符合明确中文姓名结构时才允许。单复数代词、指代词和叙事副词后缀会强制排除，避免“于是他、而是他们、但是众人、因为大家”等组合借中文姓名启发式漏过。该规则只用于启发式提取候选，不参与正式 `【角色名】` 标签可信度判断。

角色名单上下文必须贯穿候选排除和最终可信度判断。这样“阿卡菲尔”这类四字已声明人物在旁白中写直接对白时仍会被拦截，不会因为未知姓名启发式较严格而漏检。

不关闭旁白对白检查，也不只针对截图句子跳过校验。真正的人物句式（例如“苏辰开口：‘……’”）仍应被识别并报格式错误。

## 数据流

1. 恢复弹窗把原始文本或编辑后的文本传给 `handleRecoverFromParseErrorRaw`。
2. 工作流用当前正文解析选项重新调用 `parseStoryRawText`。
3. 解析器从旁白引号句中提取说话人候选。
4. 公共守卫及复用该分类器的无标签动作行提取器拒绝叙事连接词，解析器不再把“而是”当成人物。
5. 正文没有其他协议错误时，当前草稿正常重建并应用。

## 错误处理边界

- 仅消除明确叙事连接词造成的假阳性。
- 真实的未标记对白继续返回原有错误，避免降低正文协议质量。
- 如果草稿还有其他标签、判定或结构错误，应用仍应显示对应的新错误。

## 测试

- 添加截图同类长句回归用例，要求严格解析成功且正文完整保留。
- 添加“连接词动作行 + 第一人称叙述”回归用例，覆盖不经过公共守卫的平行提取路径。
- 添加“于是之”合法人物标签与未标记对白回归用例，确认整词匹配不会误伤真实姓名，也不会放过真实格式错误。
- 添加“连接词 + 单复数代词”在旁白引号和相邻动作行两条提取路径中的回归用例。
- 添加已声明四字人物在旁白中写直接对白的回归用例，确认角色名单上下文传递完整。
- 保留并运行真实人物未标记对白用例，确认“苏辰开口：‘……’”仍会被拒绝。
- 运行正文解析器测试、排除真实外部 AI E2E 的确定性测试套件和生产构建；外部 AI E2E 的网络或模型波动单独记录。
