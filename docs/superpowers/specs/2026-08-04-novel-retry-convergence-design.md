# 小说分解补漏收敛修复设计

## 背景

《六朝》任务已完成 207/210 个分段，但剩余三个分段在第 27、28 轮持续重复。浏览器日志证明失败并非渠道不可用，而是两类稳定的结构错误：模型把信息可见性写进 `内容` 文本，以及跨午夜时间仍沿用前一天日期。现有流程每次重新生成整段，未在解析后修复这些可确定的数据错误，因此补漏轮次无法收敛。

## 目标

- 从可见信息条目的 `内容` 中提取尾随的“谁知道 / 谁不知道 / 是否仅读者视角可见”，写入正式 `信息可见性` 结构。
- 当时间明确表现为跨午夜但日期未递增时，安全地推进到下一天。
- 对分段整体时间线和关键事件使用一致的跨日规范化。
- 保留严格校验；无法确定的错误继续失败并进入既有定向重试，不通过放宽校验掩盖坏数据。
- 不改动已经完成的分段，不重建 EPUB，不改变渠道故障中断策略。

## 方案

### 信息可见性恢复

在 `services/novelDecompositionPipeline.ts` 的可见信息条目规范化入口增加纯函数解析：

- 支持中文或英文冒号、斜线或括号分隔的尾随字段。
- 将“谁知道”和“谁不知道”按顿号、逗号、斜线等常见分隔符转换为数组。
- 将“是否仅读者视角可见：是/否”转换为布尔值。
- 只在正式 `信息可见性` 对应字段为空时使用文本恢复值；已有结构化值优先，避免覆盖正确结果。
- 从 `内容` 中移除已成功识别的尾随标注，防止注入和错误提示重复展示。
- 若三项均无法可靠识别，保留原内容并让现有严格校验报错。

这项修复位于 AI 结果进入正式分段结构的共同规范化路径，因此 JSON、文本解析和后续去重都会得到相同行为。

### 跨午夜时间恢复

在时间规范化阶段增加纯函数，以参考时间为基准修复明确的跨午夜日期遗漏：

- 输入时间必须是有效小说时间锚点。
- 候选时间早于参考时间时，仅在“同年、同月、同日，参考时刻位于晚间，候选时刻位于凌晨”的明确场景推进一天。
- 推进一天必须使用现有小说时间转换能力或独立的历法安全方法，正确处理月末和年末，不能直接修改日数字符串。
- 分段 `时间线终点` 以 `时间线起点` 为参考。
- 关键事件的开始、最早开始、最迟开始和结束时间依次以前一个已规范化时间为参考，保证窗口顺序和事件结束时间单调。
- 不属于明确跨午夜场景的倒序仍由现有校验拒绝。

### 补漏行为

规范化发生在每次 AI 响应解析后、完整性和连续性校验前。若本地恢复后通过校验，该分段直接写回为完成；若仍失败，既有 `retryCorrection` 会继续携带精确错误进行下一次尝试。多轮调度逻辑保持不变，但这两类确定性错误不再进入下一轮。

## 数据流

1. AI 返回分段结果。
2. 解析 JSON 或文本格式。
3. 恢复内嵌信息可见性字段。
4. 规范化整体时间和关键事件时间，修复明确跨午夜日期。
5. 执行现有完整性、时间窗口和跨分段连续性校验。
6. 通过则保存完成结果；失败则进入既有定向重试。

## 测试

在 `__tests__/novelDecompositionPipeline.test.ts` 增加真实失败形态的回归测试：

- 硬约束内容包含“谁知道 / 谁不知道 / 是否仅读者视角可见”，正式字段为空时可恢复并通过校验。
- 已有结构化可见性与文本标注同时存在时，结构化字段优先且内容被清理。
- `0003:02:28:23:59` 后的 `0003:02:28:04:00` 修复为次日凌晨。
- 关键事件跨午夜时，开始窗口和结束时间按顺序推进。
- 普通的同日倒序且不满足夜间到凌晨条件时仍然失败。

先运行新增测试确认失败，再写最小实现使其通过；随后运行小说分解相关测试、全量测试和生产构建。

## 非目标

- 不为所有时间倒序自动加一天。
- 不降低信息可见性必填规则。
- 不限制用户此前要求的自动补漏总轮数。
- 不在本次修改中重新处理或改写用户浏览器中的当前任务数据。
- 不发布新版本。
