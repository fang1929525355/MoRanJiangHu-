# 世界观生成运行时约束统一设计

## 背景

完整模式包已经支持新版动态 `currencySystem`，也允许作者分别编辑主线方向、暗线策略和世界推进规则。但当前世界观生成仍存在两条断开的数据链：

1. 世界观提示词继续读取旧版 `economy.exchangeRules`。即使作者已经把 `currencySystem` 改成单一货币，官方题材遗留的“三层货币”说明仍可能进入世界观。
2. 主线方向和暗线策略只作为世界书条目注入开场及后续剧情，不参与世界观母本生成。世界结构因而可能没有为模式包期望的主线和暗线提供合适的社会条件、冲突来源与伏笔空间。

本设计统一这两条链路，使世界观、开场、后续剧情和货币显示基于同一份模式运行时配置，同时避免世界观阶段提前泄露具体暗线或替玩家决定剧情。

## 目标

- 有合法 `currencySystem` 时，以它作为世界观货币口径的唯一真值。
- 单币种世界观明确禁止回退为题材预设的三层货币。
- 多币种世界观根据单位和 `baseRate` 自动生成一致的换算说明。
- 没有 `currencySystem` 的旧模式包继续兼容 `exchangeRules` 和旧三层货币配置。
- 世界观生成读取模式包主线方向和暗线策略，并将其转换为世界背景约束。
- 主线和暗线只塑造可供剧情生长的世界条件，不在世界观母本中生成具体任务、幕后真相、确定反派或结局。
- Web 和 Android 使用同一套提示词构建逻辑，不增加平台分支。

## 非目标

- 不改变货币余额、价格、拍卖行或角色金钱的数据结构。
- 不移除旧版三层货币字段，也不强制迁移所有旧模式包。
- 不新增通用世界书 `world_generation` 作用域。
- 不让世界观阶段生成玩家专属主线任务、主角专属机缘或具体暗线事件。
- 本次修改不包含发布、部署或版本升级。

## 方案选择

### 采用方案：专用世界观运行时约束块

世界观生成流程从开局运行时快照中读取模式包配置，构建一个专用的“模式包世界观生成约束”文本块。该文本块包含：

- 根据 `currencySystem` 生成的权威货币口径；
- 主线方向转换后的世界承载条件；
- 暗线策略转换后的伏笔与信息差边界；
- 防剧透、防主角中心化和防具体任务生成规则。

该约束块只注入世界观生成请求。原有主线、暗线世界书条目及其作用域保持不变，继续负责开场和后续剧情。

### 未采用：直接注入原始叙事世界书条目

直接把主线和暗线正文交给世界观模型改动较少，但模型容易把叙事要求写成已经发生的历史、确定的幕后组织或固定剧情结局，造成暗线剧透和主角中心化。

### 未采用：新增 `world_generation` 世界书作用域

新增通用作用域需要同步扩展类型、编辑器、导入导出、过滤器和兼容逻辑。当前需求只有三个受管叙事字段，采用专用转换层更聚焦，也更容易约束输出语义。

## 货币唯一真值

### 优先级

世界观货币提示词按以下顺序选择数据源：

1. 合法的 `modeRuntimeProfile.economy.currencySystem`；
2. 非空的 `modeRuntimeProfile.economy.exchangeRules`；
3. 官方题材 `currencyExchangePrompt`。

只允许选择其中一个来源，禁止把动态货币摘要与旧三层换算说明同时注入同一世界观请求。

### 单币种

当 `currencySystem.units` 只有一个有效单位时，提示词需要明确说明：

- 当前世界仅使用该货币；
- 该单位是唯一记账和结算单位；
- 不存在上层、中层、底层货币及层级兑换；
- 不得因为基底题材是武侠、仙侠或无限流而恢复官方三层货币。

单位名称、符号和别名从 `currencySystem` 读取。缺少符号或别名时不生成空说明。

### 多币种

当存在多个有效单位时，按 `order` 稳定排序，并依据 `baseRate` 描述各单位相对于基础单位的价值。提示词必须使用实际单位名称，不再读取旧版 `currencyTiers` 拼接第二套口径。

如果数据无法形成合法换算关系，沿用现有货币系统规范化结果；世界观提示词构建函数本身不修复非法原始配置。

### 旧模式兼容

没有显式 `currencySystem` 时保持现有行为：优先使用作者填写的 `exchangeRules`，否则回退官方题材说明。旧版三层货币编辑模式和旧存档无需迁移。

## 主线与暗线的世界观转换

### 数据来源

优先从当前开局运行时快照保存的 `modeWorldbooks` 中识别受管条目：

- ID 后缀 `-narrative-main-story` 或标题“主线方向”；
- ID 后缀 `-narrative-hidden-plot` 或标题“暗线策略”。

只读取启用、内容非空的条目。ID 后缀优先，标题仅用于兼容旧的或外部导入的完整模式包。若找不到条目，则回退模式包 payload 中保留的 `mainStoryDirection`、`hiddenPlotPolicy`；两处都没有时不生成对应约束。

### 主线方向转换

主线方向不作为既定剧情写入世界观，而是转换为以下世界承载要求：

- 社会结构和日常环境能够长期支撑该叙事方向；
- 势力关系、资源压力和公共矛盾提供适当强度的冲突来源；
- 地理与组织结构允许相关生活、探索、成长或生存活动自然发生；
- 世界不使用与主线方向相反的默认灾难、阴谋或超凡升级强行抢夺叙事中心。

### 暗线策略转换

暗线策略只定义伏笔生长条件和信息边界：

- 允许什么强度的信息差、秘密、误会、利益冲突或隐藏威胁；
- 这些暗线必须能够从人物、势力、资源、制度或历史中找到可追踪来源；
- 世界结构应保留后续调查、误判、揭露和回收的空间；
- 不得在世界观正文中点名幕后黑手、泄露真相、确定最终反派或预告结局。

### 强制边界

转换后的约束块必须明确：

- 当前阶段只生成世界母本，不生成玩家专属任务线；
- 不得围绕主角量身定做整个世界；
- 不得把主线方向写成已经发生的固定事件；
- 不得把暗线策略写成公开事实或幕后真相；
- 世界观只提供可持续承载条件，具体事件由开场和后续回合依据玩家行动生成。

## 数据流

1. 模式包编辑器保存 `currencySystem`、受管叙事字段和模式世界书。
2. 新建游戏恢复模式运行时配置与 `runtimeSnapshot.modeWorldbooks`。
3. 世界观工作流构建题材配置提示词时调用统一货币口径生成函数。
4. 世界观工作流从运行时快照提取主线和暗线，构建专用世界观约束块。
5. 该约束块与世界观种子、玩家草稿、难度规则一起传给 `generateWorldFoundationData`。
6. 开场和后续剧情继续按原有世界书作用域读取原始主线与暗线条目。

## 组件边界

### 货币提示词构建函数

放置在模式运行时配置或有效题材配置相关工具中，输入 `ModeRuntimeProfile` 和官方回退文本，输出单一、已决策的数据源说明。调用方不再自行拼接动态与旧版货币字段。

### 世界观叙事约束提取函数

放置在独立的运行时提示词工具或世界观运行时模块中，负责：

- 从模式世界书和兼容 payload 中提取受管字段；
- 去除条目包装标题和固定边界文字；
- 输出世界观阶段专用的主线、暗线约束文本；
- 在无有效配置时返回空字符串。

世界观工作流只负责调用和注入，不承担世界书识别细节。

### 编辑器提示

创意工坊经济配置中的 `exchangeRules` 文案需要明确：有 `currencySystem` 时该字段不会参与世界观和运行时货币口径，仅用于旧模式兼容。避免作者误以为必须手动同步两份配置。

## 错误处理与兼容

- `currencySystem` 只有在通过现有规范化和校验后才参与提示词生成。
- 无法读取模式世界书、条目被禁用或内容为空时，静默跳过对应叙事约束，不阻断开局。
- 外部模式包只有标题没有标准 ID 时允许兼容读取，但同类条目存在多个时以标准 ID、较高优先级和较新更新时间依次决策，避免重复注入。
- 已安装旧 APK、旧存档和旧模式包继续使用保存时的运行时数据；修复只影响使用新前端代码发起的世界观生成。

## 测试设计

### 单元测试

- 单币种 `currencySystem` 输出唯一货币说明，且不包含“三层货币”、旧单位或旧汇率。
- 多币种 `currencySystem` 按单位顺序和 `baseRate` 输出正确换算。
- 有 `currencySystem` 且 `exchangeRules` 仍是官方三层文本时，只输出动态货币口径。
- 无 `currencySystem` 时继续读取自定义 `exchangeRules`。
- 两者都没有时回退官方题材说明。
- 标准 ID 的主线和暗线条目能够生成世界观约束块。
- 标题兼容条目能够被识别。
- 禁用、空内容和重复条目不会产生重复约束。
- 输出包含防剧透、防具体任务和防主角中心化边界。

### 工作流测试

- `generateWorldFoundationData` 收到的上下文包含动态货币、主线方向和暗线策略的世界观转换结果。
- 世界观请求不包含旧三层货币污染。
- 原始主线、暗线世界书仍能在 `opening` 和 `main` 阶段注入，避免修复世界观后破坏后续叙事。

### 构建验证

- 运行相关 Vitest 测试。
- 运行 TypeScript/项目构建。
- 执行 `npm run apk:sync` 前后检查 Web 与 Android 静态资源使用同一提示词逻辑；本任务若未被明确要求发布，则只做本地构建和验证，不上传或部署。

## 验收标准

1. 作者把完整模式包配置为单一货币后，新生成的世界观不再出现题材预设的三层货币。
2. 动态多币种世界观描述与 UI、余额和市场使用的单位一致。
3. 主线方向能够影响世界的社会结构、冲突强度和可持续活动空间。
4. 暗线策略能够影响世界的秘密与信息差结构，但世界观不公开具体幕后真相。
5. 网页端和 Android 端在相同模式包、角色、模型配置下获得同一套世界观提示词输入。
6. 旧模式包、旧三层货币配置和既有存档保持兼容。
