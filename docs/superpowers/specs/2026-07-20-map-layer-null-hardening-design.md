# 地图层级空值根治与 v1.0.622 发布设计

## 背景与根因

当前 `世界.地图层级` 的状态归一化只判断字段是否为数组，未验证数组成员。当旧存档、地图更新命令或存档合并结果在数组中留下 `null`、非对象或空节点时，系统提示词构建会直接读取节点的 `层级`，在剧情请求发出前触发 `Cannot read properties of null (reading '层级')`。

## 目标

- 从世界状态入口清除非法地图层级成员，避免脏数据继续传播。
- 在提示词构建边界保留空值防护，避免未经过归一化的数据导致整个回合崩溃。
- 保留合法地图节点的字段、顺序与父子关系，不破坏既有存档。
- 用自动化回归测试和真实浏览器存档流程验证修复。
- 验证无误后在 `main` 发布 `v1.0.622`。

## 数据清洗设计

`规范化世界状态` 负责建立世界数据不变量。`地图层级` 归一化时只接受非空普通对象，并至少保留具备可识别地图语义的节点。有效节点需要具有非空 `ID`、`名称` 或 `层级` 中的至少一项；数组顺序和原对象字段保持不变。`null`、`undefined`、字符串、数字、布尔值、数组和完全空对象会被删除。

这项清洗同时覆盖存档载入、回档、变量更新与其他已经调用 `规范化世界状态` 的数据入口。合法对象不重建，避免丢失扩展字段或改变引用之外的行为。

## 边界防护设计

系统提示词中的地图层级摘要在读取节点属性时使用安全访问，并忽略非法成员。这里是最后一道防线：即使调用方遗漏世界状态归一化，剧情请求也不会因单个坏节点整体中断。

摘要中的节点数量按有效节点计算，避免界面或诊断文本继续报告已被忽略的脏节点。

## 测试设计

自动化回归测试覆盖：

1. `规范化世界状态` 会删除 `null`、原始值、数组和空对象。
2. 合法地图节点的顺序、父子字段及额外字段保持不变。
3. 系统提示词可处理包含 `null` 的未归一化世界数据，并只输出有效节点。
4. 现有单元测试、类型检查路径和生产构建不回归。

浏览器端到端验证使用现有存档导入或 IndexedDB 注入路径进入真实游戏界面，把含 `null` 的地图层级写入存档后重新加载并发起故事流程。验收重点是系统提示词构建不再抛出该 TypeError、游戏仍能进入回合队列，并且地图相关界面能够读取清洗后的状态。若外部模型配置不适合完成真实生成，至少通过应用真实的存档载入和提示词构建调用验证原始崩溃路径；不能只停留在首页。

## 发布与验收

修复验证通过后，将版本从 `1.0.621` 升至 `1.0.622`，客户更新说明聚焦“修复部分旧存档或异常地图数据导致剧情无法继续”。最终发布时间在正式构建和部署前刷新为当前本地时间，并重新同步发布元数据。

发布必须从 `main` 完成并先建立、推送发布备份提交。随后构建并验签 APK，上传 OneDrive/OpenList 与 GitHub Release，发布更新清单，部署网站静态资源。最终通过 HTTPS 分别验证主站和备用站的 `release-info.json`、`index.html` 哈希、页面版本和发布时间，同时验证 APK 下载、更新清单、公开指南入口和下载后 APK 签名。最后确认 `ypq123456789/MoRanJiangHu` 对应发布提交的最新 GitHub Actions `CI` 成功。

## 非目标

- 不重构六层地图系统。
- 不自动补造缺失地图节点。
- 不修改合法节点的层级关系或坐标语义。
- 不处理与本次空值崩溃无关的界面或运营功能。
