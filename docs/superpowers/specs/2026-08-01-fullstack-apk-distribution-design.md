# 全栈云盘 APK 自动更新分发设计

## 背景

当前 APK 自动更新主要会落到 OneDrive/OpenList 下载链路。国内无代理环境实测速度约为 25–32 KB/s，而 Android 客户端的慢速切源阈值为 30 KB/s，因此下载速度略高于阈值时不会触发切源，约 50 MB 的 APK 可能需要二十多分钟。

现有前端使用 `HEAD` 请求比较候选地址延迟，但多个候选地址只快速返回 302。这个测量反映的是跳转响应速度，不是 APK 文件的实际传输速度，可能把跳转快、下载慢的地址排到首位。

OpenList 中的“全栈云盘”挂载使用 WebDAV 驱动。现有文件的真实字节下载测试约为 0.29–2.68 MB/s，明显快于当前 OneDrive APK 链路，适合作为新的主下载源。

## 目标

- 发布 APK 时同步上传到 OpenList 的全栈云盘挂载。
- 通过网站 Worker 动态生成 OpenList 签名并返回 302，不把会过期的上游地址固化到更新清单。
- APK 自动更新优先使用全栈云盘。
- 全栈云盘失败或持续过慢时，继续使用现有下载源兜底。
- 不启用 115 Open，不把它加入公开清单或客户端候选列表。
- 保留 APK 文件大小与 SHA-256 完整性校验。
- 本任务只完成本地实现、测试与构建，不部署、不发布新版本。

## 存储布局

全栈云盘使用以下目录：

- `/全栈云盘/MoRanJiangHu/apk/latest.apk`
- `/全栈云盘/MoRanJiangHu/releases/MoRanJiangHu-v<versionName>.apk`

发布脚本通过本机或云端已有的 `MORAN_OPENLIST_AUTH_TOKEN` 调用 OpenList 上传接口。令牌只从环境变量或本地环境文件读取，不写入代码、日志、清单或提交。

## 下载链路

新增 `fullstack` APK provider：

1. 客户端请求网站的 APK provider 地址。
2. Worker 根据请求的最新版本或指定版本，定位全栈云盘中的 APK 路径。
3. Worker 使用 `MORAN_OPENLIST_AUTH_TOKEN` 调用 OpenList 文件信息接口，获取当前有效签名。
4. Worker 返回 302，跳转到 OpenList `/d/...?...sign=...` 地址。
5. OpenList 再跳转到全栈云盘的实际 WebDAV 下载地址。

签名获取失败、文件不存在或 OpenList 返回异常时，provider 返回明确错误，由客户端继续尝试后续候选源。

## 候选源顺序

更新清单默认按以下顺序发布：

1. 全栈云盘 `fullstack`
2. VPS
3. 当前仍可用的夸克 TV 通道
4. GitHub Raw/Release 加速通道
5. OneDrive

115 Open 不加入候选列表。已经废弃的 B2、R2、Hi168 不恢复。

客户端不再根据 `HEAD` 响应延迟重新打乱清单顺序，因为该数据不能代表实际吞吐。清单顺序由发布前的真实字节测速结果决定。

## 慢速切源

Android 原生下载器继续负责真实下载过程中的慢速检测与自动切源：

- 慢速阈值从 30 KB/s 提高到 128 KB/s。
- 每 5 秒计算一个真实字节下载窗口。
- 连续两个窗口低于阈值，即约 10 秒后终止当前下载并切换到下一个 provider。
- 切源前删除未完成的临时 APK，避免错误复用残缺文件。
- 下载完成后继续校验文件大小和 SHA-256。

该阈值可以排除当前约 25–32 KB/s 的 OneDrive 慢链路，同时允许全栈云盘当前测得的速度正常完成下载。

## 发布流程

仅在用户明确要求发布新版本时执行上传：

1. 完成版本号和 `releasePublishedAt` 同步。
2. 构建并签名 APK。
3. 验证 APK 签名、大小和 SHA-256。
4. 上传全栈云盘的版本化 APK。
5. 上传或覆盖全栈云盘的 `latest.apk`。
6. 分别下载少量 Range 字节和完整公开 APK，验证动态签名、Range、大小、SHA-256 与 Android 签名。
7. 发布更新清单和网站。
8. 按项目发布规则验证所有公开入口、静态资产、GitHub 备份和 CI。

本次本地开发不会执行上述上传或部署步骤。

## 测试

自动化测试覆盖：

- `fullstack` provider 能为最新 APK 和版本化 APK 生成正确的动态签名跳转。
- 全栈云盘不可用时，客户端按清单顺序切换到下一候选源。
- 更新清单把全栈云盘放在首位，且不包含 115 Open。
- 客户端不再用 `HEAD` 延迟打乱候选顺序。
- Android 下载器连续约 10 秒低于 128 KB/s 时抛出可识别的慢速异常。
- APK 大小或 SHA-256 不匹配时拒绝安装。

验证命令至少包括相关 Vitest、TypeScript 检查、Web 构建，以及适用的 Android 单元测试或 release 编译检查。

## 非目标

- 不启用或上传 115 Open。
- 不恢复 Hi168、B2 或 R2。
- 不在本任务中部署网站、上传 APK 或发布新版本。
- 不建立长期写死的全栈云盘上游临时直链。
