# 小说分解接口测试与运行诊断设计

## 目标

让玩家在小说分解接口设置页直接验证当前配置，并在小说分解任务的实时进度、重试和失败信息中一眼识别实际使用的渠道与模型，降低 404、模型不存在和配置串线问题的排查成本。

## 范围

本次修改包含：

1. 小说分解接口设置页新增“测试连接”操作。
2. 测试使用当前表单中的小说分解接口配置，即使配置尚未保存也能验证。
3. 测试结果显示渠道、模型、请求耗时和成功回复或完整错误。
4. 小说分解后台运行的关键进度、自动重试、最终失败和任务结果显示渠道与模型。
5. 规范化从模型列表读取的 Gemini `models/` 前缀，避免把资源路径前缀误当作 OpenAI 兼容模型 ID。
6. 增加自动化回归测试，并执行本地构建和日间模式可读性检查。

本次不修改发布版本，不构建 APK，不部署网站。

## 设计

### 接口身份格式

新增一个可复用的小说分解接口身份格式化函数，输入最终解析后的接口配置，输出稳定文本：

`渠道：<渠道名称>｜模型：<模型名称>`

渠道名称优先使用所选配置的用户可读名称；缺失时使用供应商或“小说分解独立接口”。模型为空时显示“未配置”。任何日志都不得包含 API Key。

### 设置页连接测试

设置页根据当前表单调用现有的 `获取小说拆分接口配置`，从而保证测试请求与真正运行小说分解时使用相同的配置解析规则。测试请求采用非流式、低温度、关闭思考输出的短消息，要求模型只返回 `OK`。

测试按钮具有三种状态：待测试、测试中、测试完成。结果区域始终先显示接口身份，再显示耗时和简短回复；失败时保留上游错误详情，方便识别 HTTP 状态码和模型资源错误。

测试不会自动保存表单，也不会改变任务状态。

### 后台进度与错误

小说分解执行器解析出最终接口配置后生成一次接口身份文本，并将其用于：

- 任务接入后的首条运行日志；
- 分段开始处理日志；
- 自动重试失败日志；
- 分段最终失败日志；
- 调度器最终结果文本。

这样实时进度和历史错误都携带相同的渠道、模型信息。流式正文内容不重复追加身份文本，以免污染模型输出预览。

### Gemini 模型名规范化

模型列表返回值进入设置页选项前移除单个 `models/` 前缀；构建小说分解最终接口配置时再做一次防御性规范化。普通模型名保持原样，避免影响带供应商命名空间的合法 OpenAI 兼容模型名。

## 错误处理

- 缺少 Base URL、API Key 或模型时，连接测试立即显示具体缺失项和接口身份，不发送请求。
- 上游失败时显示渠道、模型及错误详情，不显示密钥。
- 后台任务使用的接口不可用时，失败信息仍尽可能显示已选择的渠道和模型。
- 连接测试期间禁用按钮，防止重复请求。

## 测试策略

采用测试先行：

1. 单元测试验证接口身份文本能够正确显示渠道和模型，且不泄露 API Key。
2. 单元测试验证 `models/gemini-*` 只移除资源前缀，其他模型 ID 不受影响。
3. 组件测试验证小说分解设置页存在测试按钮，并在成功、失败时显示渠道与模型。
4. 运行相关 Vitest 测试与完整本地构建。
5. 使用本地浏览器在日间模式检查按钮和结果文本的可读性。

## 验收标准

- 小说分解接口设置页可直接测试当前表单配置。
- 成功和失败结果均明确显示渠道与模型。
- 小说分解关键进度、重试和失败日志均显示实际渠道与模型。
- 日志和界面不暴露 API Key。
- `models/gemini-*` 不再作为带前缀模型名发送。
- 相关测试和本地构建通过，日间模式文本清晰可读。
